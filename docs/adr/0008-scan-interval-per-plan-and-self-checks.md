# 8. Scan interval per plan, "check everything now" and the settings test

Status: proposed. Builds on ADR 0007.

- **The interval belongs to the plan.** A tier has `ScanIntervalMinutes` (null means the server default, `Scanning:IntervalHours`), and a tenant can override it like any other limit (a number sets it, `default` means the server default again). The starting values (Free 24 h, Starter 6 h, Business 1 h) are mine, not the product plan's, and are edited on `/limits`; Custom has none, so the management tenant of a self-hosted install behaves exactly as before. The scheduler resolves each tenant's interval once per round. It still looks once a minute, so a minute is the shortest interval, and a failed check is retried after 15 minutes whatever the interval is.
- **Check everything now** queues every applicable check of every asset of the caller's tenant, ignoring the interval, for members and admins. A tenant may do this once per cooldown (`Scanning:ManualCooldownMinutes`, default 5), kept in `tenants.LastManualRunAt`, because otherwise it would be a way around the plan's interval. Checks already waiting are not queued twice. The per-asset "Scan now" is unchanged.
- **The settings test** is a set of read-only checks that say, in the user's language, what would stop FullyQualified from doing its job, each with ok, info, warning or failed. Admins get the organization's checks: plan against usage, the interval in effect, whether results are fresh (a result newer than about two intervals, 20 minutes after a failure), alarm setup and, if asked, a real test alarm through every channel, recent alarm failures, and whether the administrators can recover from a lost passkey (two admins, more than one way to sign in). The platform owner also gets the server's: HTTPS and passkey address, proxy headers, migrations, session keys, mail server, SSO discovery, name resolution, certificate-log reachability and the public check. Server details are never sent to tenant admins. Outside calls go through one replaceable class, so tests answer for them.
- **Not included:** per-asset intervals, a quota on how often "scan now" can be used for a single asset, and fixing problems from the test screen.
