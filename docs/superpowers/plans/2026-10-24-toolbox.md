# Transient authenticated toolbox implementation plan

> **For agentic workers:** Use executing-plans for integration and dispatching-parallel-agents for independent diagnostic modules. Steps use checkbox syntax.

**Goal:** Build every approved diagnostic tool in one delivery without retaining inputs or results.
**Architecture:** Existing Blazor SSR plus small JavaScript calls authenticated antiforgery-protected POST endpoints. Stateless diagnostic modules share bounded guarded networking and structured result contracts, never monitoring runners or persistence.
**Tech Stack:** .NET 10, ASP.NET Core, SslStream, X509Certificate2, DnsClient, xUnit and existing PostgreSQL fixtures. Embed upstream Mozilla Public Suffix List with MPL-2.0 attribution; no runtime list download or domain-result cache.
**Spec:** docs/superpowers/specs/2026-10-24-toolbox-design.md, approved in conversation.

## Global Constraints

- English code/docs; all UI labels/errors/findings localized in English and Dutch.
- Authenticated access for every tool; existing sending test remains admin-only with authorized sender restriction.
- No inputs/results in database, files, logs, browser storage or result caches; no new tables, jobs, assets or plugin interfaces.
- One hosted/self-hosted implementation; honor Scanning:AllowPrivateAddresses for every direct and discovered destination and pin checked addresses.
- Defaults: 64 KiB pasted text; 256 KiB uploaded certificates or policy; eight target IPs; ten MX hosts; five-second connections; sixty-second runs; thirty requests/minute/user; four concurrent/user and sixteen/process.
- Continue existing foundation feature branch and PR #1, tracked in issue #2: master does not yet contain the application. Never merge.

## Review Focus

- Private secondary answers, MX/NS expansion and HTTP destinations cannot bypass address policy.
- Local TLS/cipher limitations must not be reported as confirmed remote rejection.
- Header authentication results are untrusted assertions, not verified authentication.
- Incomplete network probes return explicit partial/unknown status.
- Browser navigation, refresh, cancellation and bfcache cannot preserve results.

## Verified delivery

- `FQ_TEST_DB="Host=127.0.0.1;Port=55432;Username=postgres;Password=postgres" dotnet test --no-restore --verbosity minimal`: 500 passed, zero failed/skipped, including isolated PostgreSQL coverage.
- Focused browser/DOM checks: 13 JavaScript behaviors and 27 real Firefox checks against the actual SSR/API through a temporary test-auth proxy; English/Dutch, antiforgery, safe rendering, memory-only uploads, clear/reset/refresh/back navigation and mobile layout.
- Accessibility: axe WCAG 2 A/AA and 2.1 AA, eighteen rules passed, no violations or incomplete checks in the toolbox results.
- Independent review identified two important network/privacy defects and an interrupted-email-form restoration defect. HTTPS chain issuer downloads are now disabled, unsupported/oversized uploads are rejected before antiforgery form processing, and returning to an interrupted email test restores its original submit state. Regression cases were observed failing and passing.
- Full-suite runs with external `/tmp` artifact directories cannot locate the repository-root fixtures. The final verification uses the normal repository build outputs; no fixture behavior was weakened.
- Runtime limitations remain explicit: TLS/cipher probing depends on operating-system support; complete peer-supplied chains are not exposed by SslStream; SPF macro/PTR-dependent evaluation is incomplete rather than guessed.
- `docker compose up --build -d`: production images built and services started. `/health` returned `{"status":"ok"}`; `/toolbox` redirects anonymous visitors to login with `Cache-Control: no-store`; anonymous execution returns 401; toolbox JavaScript returns 200.
